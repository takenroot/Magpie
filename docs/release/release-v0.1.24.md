## Added（新增）

- [x] Windows 兼容取词（2026-11-19）：**部分应用（自绘界面的编辑器、播放器等）根本不告诉
  系统「用户选中了什么」**，划词因此永远不出胶囊。划词页新增「有些应用读不到文字」卡片：
  用户把这类应用逐条加进名单后，在该应用里选中文字时，拾趣**代按一次复制键**把文字取出，
  取完立刻把剪贴板恢复成原来的内容。**默认名单为空 = 拾趣绝不代按任何键**，正常应用也不受影响
  （只有两条系统查询都读不到文本接口的应用才会走到这一步）。
  **利害关系（须在界面明示用户，不得含糊）**：按键是真实的，拾趣无法知道目标应用此刻
  显示的是编辑区还是终端——所以主键选 **Ctrl+Insert**（它在终端里不是中断信号，实测 Zed /
  终端 / Chrome / VS Code 都能取到词），只有该应用不认这根键时才改用 **Ctrl+C** 兜底；
  名单里加了带集成终端的编辑器、在终端区拖选且主键不认时，这次兜底的 Ctrl+C 会
  **中断正在运行的命令**（残余风险收窄为这一种叠加情形，未消除）；剪贴板里刚复制了文件或截图时拾趣直接放弃这次取词（还原不了非文本
  内容，宁可不出现也不替换用户刚复制的东西）。这是「按应用授权、默认关闭」而非全局常开的
  根本原因，与 macOS 常开兼容模式的差异、键序的实测依据均记录在 ADR-05（含翻案条件）。
  为免用户不知道这里有开关：同一个应用**第三次**读不到文字时提示一次去哪开启（只提示、
  不代替用户授权，利害关系仍须在设置页那段说明里读到），同一应用本程序期间不再重复提示。
  验收：未添加应用时行为与本功能上线前完全一致（零按键）；添加 Zed 后在其编辑区划词能出
  胶囊、取词后剪贴板内容回到划词前；先复制一个文件再划词 → 不出胶囊且文件的复制不受影响；
  移除名单条目即时生效（无需保存）；黑名单里的应用即使误加进名单也不代按键；提权应用仍读不到
  （按键被系统拦截，日志有记录，界面不报错）；未授权应用连续读不到第三次提示一次、第四次起
  不再提示，已在名单里的应用与黑名单里的应用都不提示，提示是纯文字、不带任何一键授权，
  4 秒自动消失且**点一下就收场**（不得出现挂住关不掉、又点不动的提示）。
  键序验收：名单里的应用划词命中时日志给出用的是哪根键；主键取到词的场合全程不出现
  Ctrl+C；主键不认的应用才见兜底记录（该场合胶囊最多多等约 0.6 秒）。
